# MB-001 — Core application navigation

Status: implemented  
Phase: P0  
Parent: MB-E01 Foundation

## Delivered scope

MoneyBuddy now opens to a four-destination mobile tab shell:

| Area | Route | Purpose in this slice |
| --- | --- | --- |
| Today | `/` | Summarizes the sample plan and upcoming cashflow |
| Calendar | `/calendar` | Previews dated income, spending, and balance context |
| Goals | `/goals` | Previews savings progress and target outlooks |
| Journey | `/journey` | Shows how milestones fit into a longer savings story |

The custom `moneybuddy` scheme in `app.json` makes the same paths available as
`moneybuddy://`, `moneybuddy://calendar`, `moneybuddy://goals`, and
`moneybuddy://journey`. The route manifest and scheme are contract-tested.

The Today screen links to `/about`, which is presented by the root stack. Native
header back, iOS swipe-back, Android system back, and browser history therefore
use Expo Router/React Navigation behavior. Unknown paths render `+not-found` with
a route back to Today.

## Architecture introduced

- `app/` owns route composition and screen entry points.
- `src/navigation/routes.ts` is the typed core-navigation contract.
- `src/design-system/` owns visual tokens and reusable screen, card, progress,
  and state primitives.
- `src/features/` owns reusable, tested cashflow, goal, journey, and educational
  presentation components; route files only compose these pieces.
- `src/test/fixtures/` owns synthetic UI preview data.

This is UI scaffolding only. It defines no server API and performs no financial
calculation. Future screens should receive calculation results from domain and
service boundaries described in `docs/architecture.md`.

## Shared completion review

### Accessibility

- Tabs have explicit accessible labels and paired icon/text presentation.
- Primary headings use header semantics.
- links and buttons declare roles, hints, and disabled state where relevant.
- Savings progress exposes a progress-bar role and numeric value.
- Calendar dates expose full date and event labels instead of relying on dots.
- Touch targets are at least 44 points and palette pairs meet readable contrast
  targets for normal mobile text.

### Application states

The shared `StateNotice` contract supports `loading`, `empty`, `error`, `offline`,
`stale`, and `partial`. Relevant states in this static P0 slice are demonstrated:

- Calendar uses `partial` because financial inputs are not configured.
- Goals uses `stale` to identify a non-editable sample outlook.
- Journey uses `empty` to explain the pre-journal preview.
- Unknown routes use `error` and provide a recovery action.

Loading and offline do not appear during this slice because there is no async or
remote data source. They remain supported by the primitive for the first feature
that introduces those conditions.

### Data safety

Every displayed person, transaction, date, balance, and goal is explicitly
synthetic. Fixture metadata is `fixtureKind: synthetic`; no bank or user data is
read, stored, logged, or captured.

### Verification

`npm run check` runs lint, strict TypeScript, and the complete Jest suite. Tests sit
beside their design-system, feature, navigation, and fixture modules. A structural
test fails when a production module in those enforced areas lacks an adjacent
test. CI additionally runs Expo Doctor and produces a static web export so route
bundling is checked before merge.
